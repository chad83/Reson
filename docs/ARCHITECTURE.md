# Reson architecture

Reson is a native Android player with a local library and a Media3 playback service. The first milestone reads Android's existing MediaStore index. It does not modify the underlying files.

## Milestone 1

- **Presentation** uses Compose and Material 3 with system light and dark palettes. The library and full player are Navigation Compose destinations. A ViewModel exposes library and playback state as flows.
- **Domain** owns track data, metadata normalization, and the rule for playing a track in the current library order. It has no Android UI or storage dependencies.
- **Data** reads MediaStore through ContentResolver on an IO dispatcher. It queries the merged external audio collection and creates item URIs against the actual storage volume. A content observer and manual refresh update the library. The framework already indexes this collection, so a second database would add stale state without improving this milestone.
- **Playback** runs ExoPlayer in a MediaSessionService. A MediaController connects the activity to that service, which owns the current playback order and integrates with Android's media controls and audio focus. Device files use MediaStore content URIs. The service accepts track-loading requests from Reson and exposes transport controls to trusted external controllers.
- **Dependency injection** uses an application-scoped composition root and constructor injection. The local repository has one implementation and the player is owned by the service, so a DI framework is unnecessary at this stage.

See [MediaStore and shared media](https://developer.android.com/training/data-storage/shared/media), [Compose setup](https://developer.android.com/develop/ui/compose/setup-compose-dependencies-and-compiler), and [Media3 background playback](https://developer.android.com/media/media3/session/background-playback).

## Milestone 2

- **Connections** are independent profiles with an optional starting folder. AES-GCM encrypts the full saved record in private app storage with a key generated by Android Keystore. Passwords stay out of playback identifiers and navigation arguments.
- **Transport** uses SMBJ with authenticated SMB2/3, signing, and support for SMB3 encryption when requested by the server. It opens existing files and directories with read permissions and disables DFS. Share browsing uses SRVSVC to list visible disk shares. The manual share name works when enumeration is restricted. [SMBJ](https://github.com/hierynomus/smbj) · [SMBJ-RPC](https://github.com/rapid7/smbj-rpc)
- **LAN policy** accepts private or link-local addresses on a directly attached Wi-Fi or Ethernet subnet. Hostname lookups use the selected network when it has on-link DNS and no active Private DNS. The client binds its socket to that network and connects to the validated IP. The Android 17 local-network grant applies to NAS access. Optional discovery looks for SMB mDNS advertisements while the discovery screen is active. [Android local network permission](https://developer.android.com/privacy-and-security/local-network-permission)
- **Streaming** uses Media3’s progressive playback with an SMB DataSource. Each opened range has its own read-only handle, and reads use bounded SMB byte offsets. Closing a range releases the file and socket. Media3 can reopen at a different offset for a seek. The player uses only the local-content and NAS data sources. [Media3 DataSource](https://developer.android.com/reference/androidx/media3/datasource/DataSource)

## Milestone 3

- **Index** stores tracks, embedded cover thumbnails, and selected library folders in Room. Track rows use MediaStore volume-specific URIs or NAS profile, share, and path URIs. A fingerprint of the NAS endpoint and account associates each saved folder with its connection configuration. Overlapping library folders share the same track rows. Removing a folder retains entries still covered by another folder and leaves downloads available.
- **Scans** enumerate MediaStore or the selected NAS subtree and compare file revisions. Device revisions use modification time, size, MediaStore version, and generation where available. SMB revisions use last-write time and size. NAS metadata reads share one authenticated session and cap the bytes read per file. Scan changes are staged in batches, then published in one transaction after successful enumeration. Interrupted scans leave the last published index available.
- **Browsing** reads indexed metadata, loads artwork on demand, and builds the playback order from the selected track list, search results, or group. Albums use album artist where available and order songs by disc and track tags.

## Milestone 4

- **Downloads** use WorkManager for one-time transfers, opt-in folder sync, and offline playlists. Work waits for Wi-Fi or Ethernet and reuses the NAS client's LAN and endpoint checks. Folder jobs walk the selected subtree and compare SMB file revisions. Playlist jobs queue missing NAS tracks from the current playlist, reusing the same downloads across playlists and folders. A manual sync can run before the next periodic check.
- **Storage** keeps resumable partial files and completed audio in app-private, non-backed-up storage. Transfers check the expected byte count and SMB revision before publishing a complete file with an atomic move and registering it in Room. An interrupted update leaves the prior version playable. NAS deletions and stopping folder sync preserve downloaded files.
- **Playback** resolves a matching completed download before opening an SMB stream. Downloads also have local-only playback IDs so tracks remain accessible when their NAS connection or library entry is removed. The schema migration adds download and sync records alongside the existing index.

## Milestone 5

- **Collections** persist ordered playlists, favourites, and the 200 most recent playback starts in Room. A saved track uses its source and original media URI so streaming and downloaded copies share a collection entry. A saved NAS track resolves against its original connection or an available download.
- **Queue** editing uses MediaController commands on the playback service. Each queued occurrence has a separate ID, which lets the app edit duplicate tracks. The queue shows Media3's shuffle order and supports manual moves with shuffle disabled. With queue resume enabled, the service checkpoints the queue and position in app-private storage and restores playback paused.
- **Playback settings and history** are owned by the service. Shuffle and repeat survive app restarts. History records when audio starts, including track repeats, and counts pause and resume as one visit.

## Milestone 6

- **Car browsing** uses Media3’s MediaLibraryService with both Media3 and platform browser interfaces. The catalog reads the Room library, downloads, and collections and keeps large folders browsable through bounded subfolders. Browsing can refresh the device index when permission is available.
- **Access** uses Android’s media-controller trust and verifies the UID of installed system clients. External playback resolves opaque browse IDs or voice search against the current catalog. The same service still handles direct phone playback, audio focus, and standard media keys.
- **Availability** keeps downloads in the catalog when the NAS network is unavailable. Car browsing uses the current phone permissions and does not request permissions or scan the NAS from the head unit.

## Later milestones

### Storage and indexing

Android 13 and newer require READ_MEDIA_AUDIO for device-wide discovery. Android 10–12 require READ_EXTERNAL_STORAGE. The app can recover from denial through a permission retry or Android app settings. MediaStore can only return items indexed and exposed by Android. For user-selected folders outside that collection, use SAF persisted read grants, account for provider and Android folder restrictions, and limit access to local providers. Keep the identity of a NAS track separate from its cached local location and use a stronger fingerprint when matching independently imported copies. [Storage Access Framework](https://developer.android.com/training/data-storage/shared/documents-files)
